# 🔬 Security Research

I have independently conducted security research and bug bounty work focused primarily on **Android applications and web APIs**.

My research approach includes:

```text
Reconnaissance
      ↓
Application Analysis
      ↓
Attack-Surface Mapping
      ↓
Manual Testing
      ↓
Vulnerability Discovery
      ↓
Impact Analysis
      ↓
Responsible Disclosure
      ↓
Remediation
```

I don't want a security assessment to end with:

> "Here is a vulnerability."

I want the result to explain:

* What is vulnerable?
* Why does the vulnerability exist?
* How can it be exploited?
* What is the impact?
* What systems are affected?
* How should developers fix it?
* How can the organization prevent recurrence?
